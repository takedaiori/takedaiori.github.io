# 旧上游同步脚本封闭

安全复核发现 scripts/update.sh 是上游遗留的 Vercel/deploy 更新器，没有 package.json、当前工作流、README 或 docs 调用它。它不是 Notion 发文、Pages 部署、Netlify 服务器构建、图片包安装的必要步骤。

旧逻辑会切换并合并 main 后直推，随后合并并推送 deploy；这与当前强制 PR 规则冲突。它还把 .env.local 复制进 backup/，而原忽略规则没有覆盖该目录，可能在以后误提交时泄露本地凭据；测试失败也会继续。因此不再让它修改文件或 Git，保留同名入口输出明确迁移说明并立即非零退出，避免误以为已完成升级。

今后升级上游应在专用分支中逐项核对本博客定制补丁、依赖变化，经 PR 和检查后合并，再使用已有发布工作流。不能通过关闭 main 保护或给脚本 bypass 继续旧行为。

.gitignore 同时忽略本地 backup/ 和新增 Python 维护测试产生的缓存。忽略规则不会清除历史泄露，也不会取消已跟踪文件；本次检查没有发现已跟踪 backup/ 文件。若用户曾在其他副本手工提交本地环境备份，应另行检查历史并轮换实际泄露的密钥，不需要向助手提供密钥正文。

验证：bash 语法检查通过；在只包含虚构环境文件的临时目录中运行，退出码为 1，执行前后目录文件和字节完全一致。没有访问 GitHub、没有创建备份、没有调用依赖安装或部署。正常业务流程由前一项图片维护加固 PR 的全站导出、页面对照和服务器检查覆盖，本补丁不改变这些构建流程。
